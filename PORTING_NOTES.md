## Post-port fixes (2026-06-28) — vanish runtime bugs found by a full mixin audit
Triggered by a server crash report: `IllegalStateException: Cannot get config value before config is loaded` via Simple Voice Chat keepalives (`Server.sendKeepAlives → NeoForgeNetManager.sendToClient → ServerCommonPacketListenerImpl.send → vanishmod$onSendPacket`). A fan-out audit of all 28 mixins + ATs + config lifecycle (each diffed vs the 1.20.1 source and `javap`-verified against `neoforge-21.1.233-merged.jar`, every finding adversarially re-verified) surfaced five real issues. **Correction to the P10 note above:** the claim "zero InvalidInjectionException/apply failures" was inaccurate — the original `debug.log` already contained a `Critical injection failure` for `chat.CombatTrackerMixin` (logged on `entity-deserializer` worker threads, so the server still reached `Done` and it was missed).

- **Config-before-load crash class (2 sites).** `VanishConfig` is a **SERVER**-type `ModConfigSpec`; `ConfigValue.get()` throws when the config is not loaded, and a SERVER config is loaded only between server-start and server-stop. Any vanish filter that reads it off the server thread / outside that window crashes.
  - `ServerCommonPacketListenerImplMixin` (the reported crash): `vanishmod$onSendPacket` read `hidePlayersFromWorld.get()` for *every* non-vanilla packet, so an off-thread voicechat keepalive hit it during the shutdown race / config-watch reload. **Fix:** `if (!VanishConfig.SERVER_SPEC.isLoaded()) return;` after the play-listener guard, in both `send` injectors (fail-open — no player is vanished outside the loaded window).
  - `gui.ServerStatusPacketListenerImplMixin`: `vanishmod$constructSServerInfoPacket` reads `hidePlayersFromPlayerLists.get()` on the **Netty I/O thread** handling server-list pings — reachable while the SERVER config is unloaded (shutdown race). **Fix:** added `VanishConfig.SERVER_SPEC.isLoaded() &&` to the guard. (`gui.MinecraftServerMixin`'s sibling read is on the server thread after `initServer` → config loaded → left as-is.)
- **`chat.CombatTrackerMixin` — dead `@Redirect` targets (was crashing at world load).** 1.21.1 extracted the inline death-message build out of `CombatTracker.getDeathMessage` into `IDeathMessageProvider`, so the two `@Redirect`s (`getFallMessage`, `DamageSource.getLocalizedDeathMessage`) scanned 0 targets → `Critical injection failure` every time `CombatTracker` class-loaded. **Fix:** replaced both with a single `@Inject(at=@At("RETURN"), cancellable=true)` that filters the final return value (covers fall + normal death; the single-arg empty-entries generic message is untouched). Removed the now-unused `getFallMessage` `@Shadow`. **Runtime-confirmed:** new boot shows `@Inject::vanishmod$filterDeathMessage … does use it's CallbackInfoReturnable` and **0** injection failures.
- **`chat.PlayerAdvancementsMixin` — `@Redirect` missed a lambda (latent crash at first login).** 1.21.1 moved the announce broadcast into `advancement.display().ifPresent(displayInfo -> … broadcastSystemMessage(…))`, i.e. synthetic `lambda$award$2(AdvancementHolder, DisplayInfo)`; `method="award"` scanned 0 targets. Not seen in the headless boot because `PlayerAdvancements` only class-loads per-player at login. **Fix:** retargeted to `method = "lambda$award$2"` (verified the lambda contains `broadcastSystemMessage(Component,Z)` at bc offset 43; `this.player` stays accessible — instance lambda). **Bytecode-verified; needs a live login to runtime-confirm** (the lambda ordinal is build-specific but stable across 21.1.x; default `require=1` makes any future drift fail loudly).
- **Cosmetic:** `accesstransformer.cfg` comment updated (the `entries` reassigner moved to `ServerCommonPacketListenerImplMixin` post-split); removed an unused `ModList` import in `VanishEventListener`.
- **Refuted (no change):** `ServerPlayerMixin#isSpectator` reads `spoofVanishedPlayerInvisibility` but only on the server thread during active play (config loaded) — not a real exposure.
- **Re-verification:** `./gradlew build` green, `VanishVisibilityTest` 8/8, `runServer` boots to `Done` with **24** mixins applied and **0** `Critical injection failure`/apply errors.

## Config module toggles (2026-06-28) — feature add
Added a unified `[modules]` master on/off section to `config/sef/common.toml` (rendered under `[ServerEssentialsForgeModConfig.modules]`): one boolean per feature/command, default ON, the single place to enable/disable any part of the mod. Implemented by **consolidating** the 24 pre-existing scattered `enable*` toggles into it — Java field names kept (so no behaviour-gating call sites changed), TOML keys renamed to snake_case (e.g. `enableMessagingSystem` → `msg_system`, `enableChatReplies` → `click_to_respond`) and moved into `[modules]`. Detailed sub-options (formats, sounds, markdown, timestamp, integrations, scan radius) stay in their own sections. Disabling a module now both un-registers its command and skips its behaviour.
- **Three NEW toggles added + wired:** `vanish_system` (gates `VanishCommand` registration + a kill switch in `VanishUtil.isVanished`/`getVanishLevel` + `recheckVanished` login-restore, so every vanish mixin no-ops when off), `chat_formatting` (gates the `ServerChatEvent` reformat; when off, `e.setMessage(...)` keeps the filtered text and lets vanilla render the line), `op_bulletin` (gates `/opbulletin` register + startup init).
- **Defaults preserve prior behaviour:** all `true` except `nickname_command`, `discord_integration`, `custom_tab_header_footer` (`false` — need setup / conflict with FTB), matching the original Forge defaults; the 3 new ones default `true` (were always-on before).
- **Decoupled `/helpop` from `admin_chat`:** `AdminChatHandler.register` previously early-returned on `!admin_chat`, which also skipped the independently-toggled `/helpop`+`/helpopop`. Now `/ac`+`/chat admin` are wrapped in their own `if(admin_chat)` block and `/helpop` registers under its own `if(helpop)`.
- **`click_to_respond` depends on `chat_formatting`:** clickable replies need SEF to own the chat line, so with `chat_formatting=false` reply history isn't recorded. Documented in both config comments; a startup `WARN` fires if `click_to_respond && !chat_formatting`.
- **Pre-existing dead features surfaced during verification (NOT introduced here, left as-is):** `OpBulletinHandler.showBulletins` is never called anywhere (the on-login bulletin display was never wired up), and `enableDiscordBotIntegration`/`discordBotToken` are read nowhere (Discord integration is an unimplemented stub). The `op_bulletin`/`discord_integration` toggles gate what currently exists; the underlying features remain stubs.
- **Verified:** build green, `VanishVisibilityTest` 8/8, `runServer` boots to `Done` both with all toggles ON and with `vanish_system`/`chat_formatting`/`op_bulletin`/`admin_chat` flipped OFF (0 errors; the `click_to_respond`+`chat_formatting` WARN fires as designed). The `[modules]` section regenerates with all 27 toggles.
