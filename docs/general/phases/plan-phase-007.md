## Architecture and Implementation Boundaries

In network mode, the proxy owns durable home and operation records in its single SQLite writer. A backend captures and validates a `Location` and owns final safe teleport mutation. In standalone mode, where `proxyBoot` is absent, the backend owns a local persisted session namespace and durable `ArrivalReceipt`; local homes and later local RTP consumers require no proxy, bridge, profile admission or fabricated switch. A home key is owner UUID, backend ID and normalized name. Display names never authorize a choice. Import preflight inventories every legacy record, writes verified backup and count manifests, applies Unicode NFC plus casefold with bounded length and control-character rejection, maps an explicit backend ID plus immutable `WorldRef.worldGeneration`, and quarantines ambiguous name, backend or world mappings. The migration fence denies concurrent local writes before authority cutover, permits no dual writers and refuses any record that would downgrade a world generation. Explicit backend selection wins. Absent that, a current-backend match wins; a sole permitted remote match is selected; multiple permitted remote matches yield `AMBIGUOUS_REMOTE_NAME` with non-authoritative choices.

Transfer state is persisted before each outward effect. `reserve` verifies compatibility, including the observed reset-capable client profile for the approved proxy path, source session, consent, target revision and destination reservation. Missing capability refuses before the source leaves its backend; local travel does not require the external mod. Only an authenticated matching destination session advances after joining. `authorizeArrival` writes the destination durable operation intent before its one safety recheck and idempotent world mutation. The destination then writes `ArrivalReceipt` after actual movement and durable sequencing, and `finalizeArrival` writes the durable post-receipt commit only for `ARRIVED`; connection success never means travel success. A refusal becomes `FAILED` or `CANCELLED` with no unsolicited automatic fallback. Crashes before movement, after movement before receipt, and after receipt before acknowledgment remain distinguishable cut points. A lost receipt cannot cause a blind second teleport: independently reconcile actual session, location, world generation and durable operation evidence, or retain `UNCERTAIN` quarantine. Release quarantined capacity only on confirmed nonarrival. Timeout is not evidence of nonarrival.

The proposed fixture limits are test bounds, not measured performance claims: bridge frames remain at most 256 KiB, bridge queue remains 128 messages per peer with 64 in-flight requests, and each bridge request has a five-second deadline. A fixture `TransferIntent` has a separately proposed 30-second operation expiry, while bridge-envelope authorization is independently capped at 30 seconds. Neither deadline is an arrival-success timeout. The fixture accepts at most 32 simultaneously registered transfer scenarios and uses one bounded operation per participant. Phase 015 validates performance and capacity on measured workloads.

All user outcomes use existing native component adapters, literal values and normal command authorization. Rich UI action bindings may start a normal command but do not replace consent, session, visibility, revision, warmup or safety checks. Console has ordinary text status and diagnostics. All settings use validated generation swaps; no new UI configuration authority is introduced. Pending operations are bounded by inherited transfer expiration and destination readiness limits. Background work only transports bounded typed messages; world checks and mutations occur on the backend owner thread.

## Failure, Recovery, and Edge Cases

| Scenario | Detection | Required behavior | Recovery or rollback | Regression proof |
|---|---|---|---|---|
| Duplicate home names across three backends | `home.resolve` decision and permitted-choice count | Local-first and sole-remote rules hold; ambiguous remote does nothing | Ask explicit server selection and reread revision | Three-backend owner fixture with equal display names and dimensions. |
| Missing client reset capability for a remote home | `admit` profile/capability decision and independent source session/world receipt | Refuse before switch or remote reservation with a clear installation explanation; local home remains usable | Install and verify the approved external mod in a fresh supported client profile, then retry normally | No-reset isolated client request leaves source unchanged; reset-capable client completes a qualified remote home arrival. |
| World replacement after save | Captured and target `WorldRef` generation mismatch | Refuse before switch with `WORLD_REPLACED` | Preserve source session and require newly captured home | Replace disposable destination world, then retry. |
| Target unsafe after join | Destination final safety reason | Emit `REFUSED`, do not mutate and do not claim arrival | Release proven reservation, retain operation history | Change claim or hazard during switch. |
| Disconnect or session replacement | Session UUID, proxy boot, epoch and backend boot differ | Fence stale operation and never move replacement session | Cancel before authorization or quarantine after it | Rapid reconnect at every state. |
| Timeout after authorization | Missing bounded receipt with authorized transition | Set `UNCERTAIN`, never release solely by clock or fallback automatically | `reconcile` independently checks actual session, location, world generation and durable evidence; release only confirmed nonarrival | Restart proxy or destination during receipt cut. |
| Crash after movement or lost receipt | Durable intent without matching final receipt or commit | Never blindly teleport again or claim success | Quarantine, reconcile destination state and retain capacity until a receipt or nonarrival proof exists | Cut process before movement, after movement, after receipt and before acknowledgment. |
| Consent changes during warmup | Consent/session/visibility/revision recheck | Decline with safe native reason and no back write | Cancel operation and invalidate obsolete action | Move, vanish, revoke permission or switch target before apply. |
