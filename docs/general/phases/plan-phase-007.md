## Architecture and Implementation Boundaries

Documentation and evidence are read models of the frozen product, not a control plane. Registry-backed command, permission, configuration, and performance files are generated only by their existing Gradle/test owners. `README.md` remains user-facing, `DOCUMENTATION.md` remains technical and operator-facing, and `docs/README.md` maintains documentation navigation when paths change. Local closure reports retain relative sanitized evidence IDs and content digests, not raw logs or private absolute paths.

SEFAUD-IF-001 remains the reconciliation authority, SEFAUD-IF-006 remains the packet schema, and SEFAUD-IF-004 remains the existing capture interface. Local Phase 007 records carry the exact master fields first, then explicitly typed subsystem additions: `claim_id`, `evidence_id`, `candidate_commit`, `artifact_sha256`, `artifact_sha512`, `fidelity`, `invalidation_reason`, `cleanup_state`, `pr_number`, `merge_commit`, `tag_name`, `review_disposition`, and `publication_state`. These are typed report observations for closure joins, not a replacement canonical schema or competing capture schema.

Normal closure is documentation, evidence-summary, and maintained documentation/evidence-validator work only. A confirmed product defect is the narrow exception: invalidate the freeze, consult the canonical requirement contract, repair only the exact source, resource, build, runtime-harness, or acceptance-test input on this current Phase 007 branch, rerun all affected proof and the complete Phase 006 final suite after the last product change, then restart Phase 007 task 001 evidence intake. That exception never rewinds a phase/cursor/branch or edits the saved goal, plan, index, handoff, another phase file, or cursor.
