## Architecture and Implementation Boundaries

Evidence flows from a final source commit and fixed inputs to one JAR, then to isolated runtime roots, raw bounded observations, sanitized result records, and the final ledger. A runtime record joins exactly one EXT-001 host manifest. The manifest records actual OS, architecture, filesystem, Java, loader, wrapper command, dependencies, candidate, artifact hashes, fixture, config, actor, provider, world, port, evidence root, and cleanup root. A path, label, copied log, mocked OS property, parse, or callback cannot establish host execution.

The Gradle check lifecycle owns deterministic gates. The configured GameTest server run owns server-only GameTests after task-graph proof. Dedicated server runs own server claims. The laptop client owns presentation only, while the server remains authoritative for permission, identity, policy, revision, target, persistence, and mutation. Source, API ABI, artifact, installed-runtime, and Linux fixture evidence distinguish actual native/provider branches from unexecuted foreign paths. Linux, macOS, and Windows remain supported under one portable client contract; no separate foreign client session is required.
