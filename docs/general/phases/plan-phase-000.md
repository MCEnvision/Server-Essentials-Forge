## Architecture and Implementation Boundaries

The action inventory is a planning and migration boundary, not a new runtime registry. It must record observed implementation status separately from a future port decision. It preserves the current source evidence that economy services and GUI declarations are transitive kernel/configuration coupling, that menu dependent utilities are excluded, and that a server only disguise path is only eligible when independently verified. It must not claim that a source package is executable merely because it exists.

The external fixture has three distinct layers. Velocity 4.2.0 build 30 runs on Java 25. Forge 47.3.12 backends run Java 17. The isolated Forge 1.20.1 laptop client carries the exact file 4657349 JAR; the Forge server artifact does not. Ambassador, PCF and the reset mod remain separately installed external adapters with exact notices and no copied or shaded implementation. The fixture tests their combined path without becoming the later `velocity-latest` SEF product, common Java 17 contract, direct bridge, or persistent authority. It uses two disposable backend identities only to prove the required round trip switch, while the final three backend topology remains a Phase 015 acceptance gate.

Forwarded identity is treated as an authenticated property observed at the backend, not a player supplied username or a proxy log claim. The legitimate path must correlate the same UUID at laptop client login, proxy authentication/connection event, backend A admission, backend B admission, and return to A. The spoof fixture is a separate direct backend attempt with fabricated or absent proxy forwarding context. It must be rejected before the backend treats it as an authenticated player. The successful control after rejection proves that the rejection did not merely break all connectivity.

Signed chat proof requires an actual client generated signed message through the selected path and receiver side evidence that the text was accepted as a normal signed chat path. A proxy cancellation observation, a synthetic packet, or server console output does not substitute. Representative mod command proof uses the actual inventory selected server command and its normal Brigadier argument path. It records full typed input only when safe, otherwise a redacted argument shape and terminal semantic result. The switch proof uses the proxy's actual connection request result, clientresetpacket capability observation, continuous client connection, and each backend's join/leave or admission evidence. A proxy selection, disconnection or manual reconnect is not a completed switch. The missing-mod control characterizes the external adapter's failure; only Phase 005 can prove SEF's promised pre-move refusal.

The fixture uses no shared authority database, no production endpoint, no player carried administrative plugin channel, and no custom handshaking. Any later direct SEF bridge remains reserved for Phase 004 and must satisfy `SEF-IF-005`; this phase has no registered shared producer or consumer interface.
