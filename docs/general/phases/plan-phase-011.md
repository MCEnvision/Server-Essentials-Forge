## Architecture and Implementation Boundaries

`RestoreJob` is a durable server owned declaration, not a live query or a client command replay. Preview obtains an already authorized `AuditQuery` result, validates every event is declared reversible and visible to the actor, freezes per origin epoch cutoffs and stable event ordering, then persists the selected EventKeys, resources, expected current digest for each resource, dependencies, selection digest, expiry, and policy before rendering anything. The job records both the authority and configuration revision used to create it. Apply accepts only the same actor, recipient session, job ID, selection digest, and confirmation token, reauthorizes through SEF-IF-003, and then crosses to each resource's owning backend server thread.

The local job ledger is durable backend authority and is backed up independently from central SQL history. SQL query, journal, compression, and planning work are asynchronous bounded jobs. Preserve the master limits exactly: query pages default to 10 and maximum 50 rows, query deadline is 15 seconds, cursor expiry is 10 minutes, preview expiry is 60 seconds, default radius is 10 blocks and maximum radius is 100 without separately authorized broader scope, and a job may select at most 10,000 events. Larger work is explicitly partitioned with disclosed independence, never truncated. Owner mutation work is at most 64 mutations or two ms per server tick, with at most four chunk tickets and a five second resource acquisition timeout. Exceeding a limit returns a typed refusal or leaves a durable `PARTIAL` or `UNCERTAIN` job without further mutation. No worker reads live world state or modifies a live object.

The owner executor records a durable local step `INTENT` before a group mutation and records its post mutation digest and outcome immediately after. Persistence runs off the owner thread; mutation waits for its durable receipt, then rechecks current permissions, claim policy and resource state on the owner thread. Local job storage and the world are not one transaction, so missing acknowledgement after mutation is `UNCERTAIN`, not success or failure. Startup reconciliation obtains a fresh owner thread observation under the same world generation, registry digest, and resource identity. It may classify only exact before or exact after state. Any ambiguous, unloaded, offline, missing registry, missing snapshot, redacted payload, gap, changed generation, or altered current fingerprint remains quarantined. There is no blanket retry and no operator force mode for those cases. Multi-backend jobs expose per-backend partial progress rather than claiming distributed atomicity; P011-TASK-001 conservation evidence compares those recorded outcomes with each backend's independent resource observations.

Rollback applies its fixed selected event IDs in reverse causal dependency groups. Restore references the exact completed applied job and its recorded resources, never a fresh query or changed filter. Undo creates a child job from exactly the resolved `APPLIED` subset of its completed parent, reverses it in reverse dependency order, and excludes skipped, failed, conflicting, and uncertain steps. Resolved partial jobs preserve that same boundary. Repeated apply, confirmation replay, repeated undo, and cancel after a terminal state return `ALREADY_APPLIED` or the recorded terminal state without duplicating inventory. Recorded item give requires an explicit new `sef.audit.give` permission which defaults denied even under the audit wildcard, a distinct explicit confirmation, fresh target authorization, registry and NBT validation, bounded stack quantity, and an independent audit event. It does not amend a restoration job, spill compensation, resurrect a death drop twice, or duplicate an entity UUID.

Preview is private server native presentation under SEF-IF-004. For representable selected block changes it sends private vanilla block change packets; all selected resources receive complete text summaries and conflict reports. It must never be persisted as authority, sent to unauthorized observers, mistaken for a visual world mutation, or implemented through a custom client protocol. It rechecks current resource and observer visibility state, then clears private packets and restores authoritative display before each terminal write and on chunk reload, resource changes, SEF-IF-008 transfer, world or session changes, cancellation, expiry, disconnect, apply, reload, failure, shutdown, and restart. The transfer or session transition invalidates preview and confirmation rather than retargeting either. Gaps, private redactions, opaque snapshots, unsupported adapters, and nonreversible events show a localized refusal and never an exact preview or confirmation token. The Phase 015 consumer receives the stable ledger and evidence contract only. It is not a prerequisite for Phase 011 closure.
