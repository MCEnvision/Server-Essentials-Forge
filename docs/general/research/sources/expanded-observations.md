#### Restoration design and safety boundary

An event is not automatically reversible. Persist a reversibility class, schema/adapter version, complete required preimage/postimage, registry fingerprint, operation/cause ID and source sequence. Interaction/chat/session/movement log entries are evidence, not actions to replay into the world. Missing secrets or omitted private capability data can make a payload unsuitable for exact restoration; mark that limitation rather than recreating an invalid object. Queryable redacted metadata and protected restoration payloads need separate access controls and size/depth limits. Never deserialize arbitrary Java objects from a row or permit NBT to execute commands during preview.

Build each restoration as an immutable job with selected event IDs, snapshot cutoff, affected-resource set and per-step expected-current fingerprints. Rollback processes dependency groups in reverse causality; restore reverses the particular rollback's actual changes, not an unbounded requery of current history. Undo references that exact job. Acquire sorted short-lived resource locks on the owning server executor; process bounded batches and release chunk tickets. Before each mutation, recheck world generation, dimension, registry availability, chunk readiness, permissions, player session, claim policy and the current fingerprint. Conflict means skip/report or stop according to explicit job policy, never overwrite newer player work silently.

Inventory groups include both ends of a transfer, associated item entities and affected live/offline player inventories. Pause relevant interaction/automation only for the bounded owned transaction, reject if a full destination prevents exact restoration, and never spill unmatched items automatically. Do not reverse only the destination while leaving the same items in a player's inventory. Items crafted or moved onward after the selected event require a provable dependency chain or a conflict; never manufacture compensation items to pretend full reversal. A privileged recorded-item give deliberately creates an item, must say so, require confirmation and be audited distinctly from restoration. Entity resurrection checks UUID collision, passengers, equipment, drops and death-loot linkage. Removed mod registries, opaque capability state, changed dimensions, stale offline records and ambiguous automation lead to actionable unsupported/conflict results.

Use durable job intent and per-step journal, then world mutation, then durable applied record. Minecraft world state and SQL are not one ACID transaction. A crash between those stages requires reconciliation against both expected-before and expected-after fingerprints; other states quarantine the step. Replaying an uncertain step blindly is forbidden. Database rollback cannot undo a world mutation. Partial completion remains a partial job with exact applied/skipped/failed/unknown counts and retry/compensation paths. Restoration events carry original-job linkage and an explicit restoration origin so ordinary capture does not create a recursive undo loop. Multi-backend jobs are coordinated bounded jobs, not falsely atomic global transactions.

#### Storage, loss reporting and privacy

Recommend disposable verification on MySQL8.4 LTS and MariaDB11.4 LTS with exact server, driver and image/artifact digests. Declare those tested families first; do not imply all older/newer MySQL-compatible versions work. Use InnoDB, explicit UTC timestamps, binary UUID/event IDs, portable text/blob schemas, explicit collations and prepared statements. Test migrations, duplicate IDs, deadlocks, retry boundaries, backup recovery, bulk purge and index query plans separately on both dialects. Do not depend on vendor-specific JSON/generated-column behavior unless isolated by tested dialect code. Proxy SQLite can remain the low-volume network-authority store; audit ingestion and query work must not starve moderation or homes.

Each backend owns an append-only segmented spool with monotonic sequence and authenticated server identity. SQL ingestion is idempotent by origin/epoch/sequence and acknowledges only committed batches. Replay survives restarts; corrupt tails are isolated, never mistaken for valid events. Size limits cover memory, segment count/bytes, payloads, pending jobs, query concurrency and timeouts. Redact known sensitive command arguments and credential-like values before the first spool write. Restrict full private content separately from ordinary block lookup. Raw arbitrary NBT may contain credentials or private text; typed adapters must identify sensitive paths, with protected/redacted handling and an explicit nonreversible marker if required state cannot be retained safely. Do not claim a generic regex guarantees detection of every unknown secret.

At local capacity failure, rotate only the oldest verified SEF-owned closed segment within the configured canonical spool directory, with symlink/path defenses. Never delete the active segment mid-write, unrelated files, control databases or central SQL rows. Emit durable loss metadata where possible before removal: origin epoch, sequence range, time range, reason, affected categories/count if known, and acknowledged versus unacknowledged status. Keep a small reserved loss-ledger capacity and coalesced ranges; if even it cannot be persisted, maintain an in-memory degraded counter and report unknown lost extent after restart rather than an invented exact count. The next successful SQL ingest records the gap so lookups and rollback eligibility expose it. Manual retention is not infinite physical durability under the owner's availability-first choice.

Admin-only health shows active degradation, oldest pending age, queue/spool occupancy, rotation count, gap ranges, SQL state, webhook delivery state and last recovery. Configured Discord receives concise operational state changes and recovery summaries, never private chat, full commands, NBT, credentials, webhook URL or automatic mass mentions. Restrict destination configuration, disable redirects or validate every hop, and do not allow a player-supplied arbitrary URL. Coalesce alerts, bound retries/outbox, honor429 retry metadata, back off on failure and retain local visibility when delivery fails. Test with an owned mock endpoint; no production credential or external Discord message is necessary for acceptance.

### Hierarchical RTP algorithm and lifecycle

The reference implementation samples an annulus around a saved center and skips unloaded chunks. It offers no evidence for the requested grid guarantees. The new grid is an independent mandatory subsystem integrated with existing permission, cooldown, warmup, history and safety services after economy removal. Keep the local-only mode fully functional without Velocity.

Use a stable grid identity containing backend ID, persistent world-generation ID, dimension key, inclusive configured integer bounds, parent rows/columns, subcell rows/columns and policy revision. Validate finite limits, positive counts, at least two parent cells, nonempty subcells, bounded total state and legal world-border intersection. Partition width W into n disjoint integer intervals with boundaries `min + floor(i * W / n)` using checked wide arithmetic; use half-open internal intervals and convert inclusive configuration once. The final boundary is exactly max+1. Apply the same rule inside each parent. It handles negative coordinates and uneven division without gaps or overlaps. Uniform parent choice is fairness by section, not uniform area if section sizes differ; choose actual x/z uniformly within the selected subcell, then determine safe y. Never always use a cell center.

Persist a shuffled parent permutation, cycle ID, remaining/committed/reserved sets and last committed parent. Persist an independent subcell permutation/cycle/last-committed state for each parent; selecting another parent or reshuffling the parent bag does not reset its subcell progress. Use an unbiased Fisher-Yates shuffle with an injected RNG for deterministic tests. At a cycle boundary, condition the next shuffle on first != last actual committed entry, using rejection or an unbiased eligible-first selection followed by shuffling the rest. Do not merely rotate a sorted list and call it random. Apply an equivalent boundary rule to each subcell bag when it cycles; reject one-cell dimensions when that rule cannot be met. Persist permutation/state rather than relying only on an RNG seed whose draw count may change across versions.

The resolved consumption point is successful arrival. Allocate a durable provisional reservation for parent, subcell, candidate region and operation ID before committing a destination. A parent may have only one consuming reservation in its current cycle; concurrent requests use different remaining parents. A reserved cell is not available to another request. Candidate preparation is not consumption. Searching can reject unsafe candidates within bounded attempts, or try another currently unused eligible parent/subcell without recording a successful use. Failed/cancelled requests release only after confirmed non-arrival. Do not permanently mark a blocked cell used merely to finish the cycle. If every remaining unused cell is unsafe, unavailable or reserved, queue briefly within explicit capacity/deadline or return unavailable. Never restart the bag, reuse a committed entry or lower separation distance to satisfy a request.

A cycle advances only after every entry has a committed landing and no unresolved reservations remain. This makes the cross-cycle guard use the last actual landing, not the last selection request. Because completion order can differ from reservation order, a new-cycle reservation cannot be made early using a guessed final entry. Within a parent's subcell cycle the same barrier applies. Keep reservation/commit operations serializable through the owning backend coordinator and persistent transaction; network retries carry the same ID. Tickets and leases have owner/session/epoch fencing so a restarted coordinator cannot race an old one.

Journal prepared, arrival-authorized, arrival-observed and committed states. Before actual teleport, durably retain an intent and the exact destination. After actual arrival, record the successful landing and bag consumption idempotently, plus recent-landing exclusion and audit linkage. SQL/local persistence and player world position are not atomically committed together. On recovery, release only a proven non-arrival; reconcile durable player/session/location evidence for observed arrivals; quarantine ambiguous reservations until resolved. A timeout alone after arrival authorization is not proof the player did not arrive. This may temporarily exhaust a grid, but avoids repeating an uncertain used section. Audit rotation must never rotate the authoritative RTP reservation/bag store; if that store cannot persist safely, deny new RTP while ordinary gameplay continues.

Reconfiguration creates a new immutable grid generation, not an in-place reinterpretation of old cell numbers. Drain/cancel provisional work with confirmed non-arrival, quarantine uncertainty, and retain old state until reconciled. Changes to bounds/cell topology must show that fairness history is restarting; do not silently reset bags on every reload. Preserve historical state keyed by generation for diagnostics and migration. Restart, world replacement and dimension deletion must not map an old reservation into a different world with the same name.

#### Separation, safety and prepared supply

Recommend explicit horizontal XZ Euclidean distance as the default separation metric, with distance and recent-landing duration named in configuration; it prevents adjacent vertical cave landings from defeating the crowd-spacing intent. Document the chosen metric and equality boundary. Independently enforce minimum distance from all online players in the destination world, every live reservation and all recent successful landings inside the configured time window. Vanished players count without their identity/location leaking into denial messages. Use a spatial index only as an optimization; compare exact squared distances for candidates. The recent ledger must survive restarts for its stated window. If its configured capacity cannot preserve the entire live window, apply admission backpressure rather than silently evicting entries early.

Claim access, border/build height, dimension rules, solid safe footing, body clearance, liquids/fire/hazards, biome restrictions when configured, and world/chunk identity are separate from distance checks. Revalidate at final arrival on the owning server thread, after warmup and after any proxy transfer, because players, claims, blocks and hazards can change. A player moving into a reserved destination can invalidate it; reserve a replacement safely or fail without consuming the section. Permissions, cooldowns, vanish, moderation restrictions and session must also still permit arrival. Do not teleport to an unsafe fallback spawn and call RTP successful.

Prepared candidate pools contain expiring proposals tagged with grid/policy/world revision and safety observations. They do not spend either bag. Count prepared supply only for currently eligible unused cells, not raw cached coordinates. Chunk loading/generation must be an explicit bounded preparation policy: main-thread-compatible APIs, per-tick work budgets, concurrent ticket limits, cancellation, timeout and exact ticket release. No world generation on network or SQL worker threads. The existing loaded-only behavior is the safe initial capability; optional bounded preparation must earn real chunk/claims/hazard evidence before being advertised. Neither a high candidate count nor a passed old heightmap check guarantees arrival safety.

#### Optional proxy-first routing

The proxy first filters configured backends by readiness, pack compatibility, world/grid eligibility, moderation rules, authenticated session and fresh telemetry. Rank remaining destinations using normalized MSPT relative to the tick budget, recent spike pressure, configured player capacity plus incoming reservations, chunk-work pressure and usable prepared supply. World area or world file size is not a capacity measure. Do not compare raw player counts across unequal capacity settings. Stale/missing telemetry excludes automatic routing rather than assuming zero load. Use signed/authenticated sequence, backend epoch and expiry through the independent admin bridge, bounded sampling windows, hysteresis and admission leases to prevent all concurrent requests choosing the same momentarily idle server.

Reserve backend admission and destination resources before switching; otherwise keep the player on the source with actionable unavailable feedback. Lease renewal and eventual cancellation must fence stale messages. Destination final checks and idempotent arrival determine success, not the proxy's connection callback alone. Release incoming capacity on confirmed terminal outcomes; quarantine ambiguous arrivals. Failover may choose another eligible backend only before a committed/uncertain arrival and while all invariants remain satisfied. Do not silently route to an incompatible pack or convert local mode to proxy mode when the local grid is unavailable. Staff diagnostics explain eligibility, telemetry freshness, pressure factors, pending reservations and rejection categories without exposing players' private locations.
