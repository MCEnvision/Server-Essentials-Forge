### Scope and event coverage contract

PROPOSED product interpretation: comprehensive, queryable server-observable actions and resulting state changes for declared supported hooks and adapters. This is an investigation event log, not a deterministic replay of the entire simulation, a packet recorder, a source-code debugger or a guarantee of recovering arbitrary mod internals. Publish an explicit coverage registry keyed by Minecraft/Forge version, mod ID/version, event family and adapter revision. It must identify supported, partial, unsupported, disabled, redacted and unhealthy coverage. Query results carry applicable gaps and watermarks; an empty result must not imply that nothing happened during uncovered periods.

For every mutation record distinguish attempted, denied, cancelled, applied, partially applied, failed, and outcome unknown. Capture immutable before/after copies at authoritative mutation points. A listener at the last event priority is not automatically a post-commit hook. A later tick snapshot can miss two opposing changes within one tick. Prefer verified method boundary hooks for missing post events, narrowly scoped mixins when needed, and explicit integration adapters for opaque storage. Never relabel an approximation as exact.

### Storage and durability recommendation

The new high-volume requirement changes the architecture recommendation for audit data only. PROPOSED preferred deployment: each Forge backend writes a durable local journal and streams acknowledged, idempotent batches directly to a dedicated external SQL audit database. The proxy remains a small permission-aware query coordinator and emits its own network events. It does not serialize world NBT or receive every raw event on its game/network event loop. Keep moderation and transfer state independent so a costly world-history query cannot stall login bans.

| Alternative | Advantages | Consequences |
| --- | --- | --- |
| Three local SQLite journals and live federated queries | No new database service, isolated ingestion and failure domains. | A stopped/unreachable backend cannot answer its history. This alone fails the requested offline-backend investigation behavior. |
| Local SQLite journals plus centrally replicated SQLite audit archive, separate from network-state DB | Minimum new infrastructure. Committed replicated history remains queryable while backend is offline. | One archive writer and shared query resource require measured bounds. Archive service/process and large-dataset operation add complexity even without external SQL. Unreplicated tail remains unavailable and must be shown. |
| Dedicated external SQL audit dataset plus per-backend journal | Central indexed queries, existing operator database/backup tools, offline backend access and independent ingestion. | Requires actual database engine/version, access and capacity choices. Network outage spools locally; full spool remains a failure policy. Do not write directly to an unrelated existing application schema. |

The owner offered a third database. Recommend this dedicated audit dataset if an existing supported MySQL/MariaDB or PostgreSQL service is available and approved, while implementing exactly the chosen dialect initially. Do not silently promise all SQL engines or require new paid infrastructure. External SQL is recommended for this workload but is not logically mandatory: central SQLite replication is a credible lower-infrastructure alternative if measured peak volume and investigation latency meet the selected gates. Whichever choice is made, retain local journals because remote writes alone cannot guarantee capture during network outages.

PROPOSED event identity and ordering: immutable `(serverId, journalEpoch, sequence)` identity plus globally unique event ID, wall-clock UTC, local monotonic ordering, world identity, registry/schema version and boot/session generation. Use parent links for causal order across hosts; synchronized timestamps do not establish a total order. Central ingest commits a batch and its high-watermark transactionally before acknowledging. Retries reuse IDs. Local deletion requires confirmed central durability and the chosen local recovery window. Never discard an unacknowledged segment just to satisfy an ordinary retention timer.

PROPOSED crash protocol: journal segment header/schema, length-delimited records, bounded payloads, sequence continuity and checksum; maintain persisted segment manifests and clean/unclean shutdown state. On restart detect torn tails, quarantine damaged segments and retain a coverage discontinuity; replay intact committed records idempotently. Distinguish captured, locally durable, centrally durable and query-visible watermarks. A RAM enqueue is not durability. Group commit gives throughput but has an explicit unsynced-tail crash window. A universal zero-loss world/audit transaction is not provided by Forge: world saves and audit commits are separate systems. To narrow uncertainty, reserve journal capacity before supported mutation, persist intent and then outcome; unresolved intents after a crash remain uncertain until reconciled. Never claim those intents prove applied changes. Hardware failure and hostile administrator edits are separate limits; a local hash chain detects some alterations but is not independent tamper-proof evidence.

PROPOSED backpressure: bounded capture queue, record byte size, per-tick work, segment size, replication batch size, retry delay, query pool and result size. Default diagnostics expose queue depth/capacity, oldest unflushed age, unacknowledged bytes, disk reserve, ingestion rate, last committed sequence and active coverage health. Thresholds need measured workload selection. No fictional throughput figures are asserted. An oversized record preserves type, identity, safe digest and explicit omission reason, not silent truncation represented as a complete snapshot.

Material failure policy: finite disk and bounded queues cannot preserve unlimited events while the server continues indefinitely. The earlier strict-stop alternative is superseded by DEC-012. The owner selected continued gameplay, oldest SEF-owned local closed-segment rotation and explicit gap reporting. Preserve a durable gap interval/counter when possible and prominent degraded coverage; it cannot be called complete retained history. Emergency failure can still leave an uncertain tail, which must be reported on restart. Normal retention remains manual purge under DEC-010; emergency rotation does not authorize central SQL deletion.

Retention must be explicit and must cover event rows, blobs, indexes, replicas, backups and exports. Automatic age deletion, manual-only deletion and unlimited history have different operational implications. Purge needs scoped preview counts, explicit confirmation, permission, audit record, exclusion of pending unreplicated segments, and tested recovery/backup policy. A purge is intentional removal, not a silent logging loss. Capacity estimates come from representative event rate times measured serialized bytes and chosen retention, plus indexes, journals and replication/backup overhead.

### Investigation behavior without custom interface

PROPOSED text-only command surface: status/coverage, inspect toggle, lookup, near, event detail, cause chain, count/summary, page/cursor and permitted export. Interactive inspection uses vanilla clicks with server-generated text and prevents the inspected click from mutating the target where supported. It requires no screen, custom inventory menu, HUD, client payload or resource pack.

Filters cover server, world identity/dimension, coordinates/radius/box, UTC time range, actor UUID/current or historical name, fake player/machine, action family, item/block/entity registry ID, operation outcome, confidence, correlation ID and redaction class. Stable cursor pagination pins a query snapshot/high-watermark so ingest cannot reorder pages or duplicate records. Scope permissions are checked for every page and export, not only initial lookup. Query worker pools enforce time and row budgets, cancellation and parameterized SQL; broad searches return explicit bounded continuation rather than freezing ticks. Output labels partial coverage, offline server, unreplicated tail, retention cutoff and unknown attribution. Historical records retain registry IDs even when the current pack cannot render the original item; unknown mod data remains readable as sanitized metadata, never instantiated as live game objects.

Rollback, restore, undo and preview were subsequently approved in DEC-008. A log alone is insufficient: supported reversible types, before-image completeness, live-state conflict checks, fixed preview selection, bounded per-tick apply, object dependencies, inventory conservation, durable jobs, cancellation and recovery are mandatory. Opaque machine internals and external services cannot be universally reversed. The expanded observations define the approved restoration boundary.

DEC-009 selected full public and private content with credential redaction and separately restricted access. redact known credential commands, tokens, forwarding/bridge keys and configuration secrets before memory queues, journal files or SQL ingestion. Preserve redaction reasons so missing content is explained. Private-message content, exact locations and vanished staff actions require distinct permissions and access auditing. Unknown mod command schemas and opaque NBT can contain secrets; a conservative field allowlist and adapter contract are safer than storing every byte. Do not promise perfect automatic secret detection in arbitrary free text. No unrelated chat/service logs are imported.

### Required real-path proof

These are concrete proposed tasks, not tests performed. Each needs the exact disposable runtime, pinned modpack, teardown and sanitized evidence.

1. Instrumentation ordering: cancel placement/break/damage at a later priority, replace one block twice in one tick, create a multiblock, run explosion with changed candidate list and fluid on a waterlogged block. Compare actual final world plus per-operation mutation sequence with journal. No cancelled intent is labelled applied and no second change disappears in a tick-end diff.
2. Inventory conservation: use real menu interactions, shift/drag/number keys, cursor stacks, creative changes, hoppers, a supported modded item-handler pipe, partial insertion, simulation, nested storage, crafting remainders, full destination, machine cancellation, container break while transferring and same coordinates in separate worlds. Record independent before/after endpoint inventories and dropped entities. For each flow, actual source decrease equals sink increase plus explicit consumed/produced/dropped legs; simulated calls contribute zero. Recipe transformations use recipe accounting. Expected counts come from independent fixture observations, not the audit implementation itself.
3. Cause integrity: player starts a machine, leaves the server, machine later executes; two fake players operate concurrently; scheduled command wraps another command. Audit must distinguish known initiating context from unknown ownership and never leak a stale thread-local actor into unrelated work.
4. Crash and outage: interrupt after capture, local commit, remote commit before ack and ack before local cleanup. Restart with incomplete final record and replay duplicate batches. Every durable event has one central identity, uncertainty/gaps are visible, unacknowledged records survive, and queries identify stale watermarks. Interrupt the backend while central storage remains online and verify its replicated history remains searchable.
5. Capacity: replay measured representative vanilla and machine workloads at expected peak and controlled bursts while simultaneous bounded investigations run. Observe tick latency, allocation/GC, journal fsync latency, query latency, bytes/event and replication catch-up. Inject slow disk, unavailable SQL and full-disk thresholds. Prove the selected protective or degraded policy activates before silent queue loss. Do not replace real-path inventory proof with synthetic event calls.
6. Privacy and scope: known secret commands, unknown mod commands, nested command wrappers, malicious NBT, private text, ordinary/staff/vanished subjects, permission revoked between pages and exports. Verify secrets never appear in any sink, sensitive records obey owner policy, and read access itself is audited without recursion.
7. Movement: walk, fly, vehicle travel, server corrections, teleport, dimension change and cross-server handoff. Compare accepted authoritative updates with the selected motion mode. Test intermediate moves within one tick if full mutation mode is selected; tick snapshots alone cannot satisfy that oracle.
8. Offline history and retention: stop a backend, remove an old mod from the query environment, query old registry IDs, hold a query cursor across new ingest, preview/purge only authorized old history and validate retained sequence ranges. Unknown/expired/unreplicated history must not display as complete empty results.
