# Forge 1.20.1 Proxy Compatibility Clarification

Observed 2026-09-25T18:57:20Z. The owner selected Ambassador, ProxyCompatibleForge, and CurseForge file `4657349` for Forge 1.20.1 network compatibility. This is permission to qualify a separately installed external client reset mod, not to add an SEF client module or promise arbitrary modpack replacement.

The [exact CurseForge file](https://www.curseforge.com/minecraft/mc-mods/forge-client-reset-packet-forward/files/4657349) is `ForgeClientResetPacket-0.3.0.jar`, uploaded July 21, 2023, and lists Forge 1.20 and 1.20.1. Its project page marks the environment as client and declares MIT. The project also lists a later 0.3.1 file; that is not the owner's linked artifact. The retrieved JAR is 12,847 bytes. Its `META-INF/mods.toml` declares mod ID `clientresetpacket` and internal version `0.0.6`, so the file release label and embedded mod version must not be conflated. The archive points to an upstream license URL; inspect the distributed and upstream notices before operator distribution. The byte hashes are recorded in [network artifact integrity](network-artifact-integrity.md). This is artifact inspection, not an executed compatibility test.

The [Ambassador project page](https://modrinth.com/plugin/ambassador) documents matching-mod switching without an added client mod in some setups and also documents reset-packet switching. The [pinned 1.4.5 source](https://github.com/adde0109/Ambassador/blob/v1.4.5/src/main/java/org/adde0109/ambassador/forge/VelocityForgeClientConnectionPhase.java) selects its resettable path when the client advertises `clientresetpacket`; without reset or redirect capability, its complete-phase path can disconnect with a reconnect instruction. The [earlier Phase 000 fixture result](../../../verification/phase-000/fixture-result.md) achieved login, forwarded UUID, signed chat and command arguments, but A to B and B to A requests disconnected the no-extra-mod client. Manual reconnect did not establish an in-session switch. The revised Phase 000 fixture must prove the full path with the pinned reset JAR, then preserve a missing-capability control as diagnostic evidence. A fresh laptop client and server test, not source inspection, decides support.

[ProxyCompatibleForge's documentation](https://modrinth.com/mod/proxy-compatible-forge) describes its Forge backend forwarding and command wrapping role. It notes Ambassador 1.2.0-beta or newer does not require PCF merely to establish a proxy connection, while PCF remains available for modern forwarding. The selected network profile keeps PCF because authenticated modern forwarding and command argument behavior are explicit acceptance targets. The three artifacts have distinct placement: Ambassador on Velocity, PCF on Forge backends, and the reset JAR in the compatible Forge client profile. Keep SEF server-only.

The reset packet does not install missing destination mods. A directed cross-pack relation remains unqualified until one unchanged running client with its actual mod/config/registry profile completes real transfers through the selected adapter matrix. SEF's later admission policy must refuse a missing observed reset capability, unknown or stale relation, or incompatible destination before starting movement. This early refusal is a product responsibility; the independent Phase 000 adapter fixture cannot itself prove it.
