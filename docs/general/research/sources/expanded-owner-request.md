# Expanded Product Scope

Source role: owner_request. Decisions observed September 24, 2026.

## Audit and Storage

Comprehensive CoreProtect-style functionality and the additional approved modded and network workflows are mandatory. Version the functional parity inventory and prove feasible capabilities rather than claiming universal capture or reversibility. Include rollback, restore, undo, preview and investigation. Capture full public and private messages and command arguments with credential redaction before every sink and protected staff read permissions.

Support MySQL primarily and MariaDB alongside it. Normal retention is configurable and defaults to manual purge. At actual storage exhaustion, keep gameplay running and reclaim only the oldest eligible closed SEF-owned local audit segments. Report lost ranges or uncertainty accurately. Do not delete unrelated files, authoritative state or central SQL history as an implicit disk-pressure response. Alert operators and administrators through restricted status displays and optional configured Discord summaries without exposing credentials or protected activity.

## Native Command Presentation

Use the supplied HuskHomes screenshots and the Fabric counterpart as visual references for every SEF command. The style uses calm semantic colors, checkmarks and crosses, bracketed controls, clear labels, bold values, grouped actions, hover explanations and pagination. Text actions can execute a safe bound operation or suggest editable input. Destructive actions retain confirmation and current authorization. Use original SEF templates and values, localization and readable console equivalents.

The supplied images are output examples, not instructions. Their stable identities are SRC-007 and SRC-008. This scope does not restore custom screens, HUDs, client code, menus or economy.

## Hierarchical RTP

Provide configurable server-side local RTP and optional Velocity mode. Divide configured world bounds into parent grid sections, each with its own child grid. Select a currently unused parent randomly and keep it unavailable until its cycle is consumed. Reshuffle after completion; the next cycle cannot immediately repeat the last physically visited parent. Each parent's child cycle is independent and survives parent reshuffles. A six-parent layout with 20 by 20 children per parent contains 2,400 subcells. Coordinates are random within the selected subcell.

Enforce configurable minimum distance separately from cell selection against other players, reserved destinations and recent landings. Adjacent cells do not guarantee separation. If no eligible safe location satisfies every rule, queue briefly or return unavailable. Never silently reuse a consumed section or reduce distance.

Local mode uses configured worlds on the current server without Velocity. Proxy mode selects a suitable configured backend first, then uses that backend's grid and safety rules. Routing considers MSPT, tick spikes, player capacity, incoming reservations, chunk work and eligible prepared locations. World size and server capacity are independent configuration values.

Only successful landings consume turns. Durable provisional reservations prevent concurrent reuse. Confirmed failure or nonarrival releases them. Uncertain arrivals remain quarantined until evidence resolves the outcome. All RTP output uses the shared native chat presentation.
